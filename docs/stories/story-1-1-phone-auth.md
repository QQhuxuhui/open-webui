# Story 1.1: 手机验证码认证系统

## User Story

作为Open-WebUI用户，我希望使用手机号和验证码注册登录，以便符合中国实名认证要求。

## Story Context

**现有系统集成：**
- 集成对象: 现有JWT认证系统 (`backend/open_webui/apps/webui/routers/auths.py`)
- 技术栈: FastAPI + Peewee ORM + JWT
- 遵循模式: 现有用户认证和token生成模式
- 接触点: User模型、认证中间件、前端登录组件

## 验收标准

**功能需求：**
1. 用户输入手机号后可接收6位数验证码
2. 验证码5分钟有效，支持60秒间隔重发
3. 注册时强制勾选隐私协议和服务协议复选框
4. 验证成功后生成标准JWT token

**集成要求：**
5. 现有用户名/邮箱登录功能保持完全不变
6. JWT token格式与现有系统完全一致
7. 用户session管理和中间件无任何影响

**质量要求：**
8. 包含前后端集成测试覆盖
9. 验证码发送限流：每分钟1次，每小时5次
10. 现有认证功能回归测试通过

## 技术实现细节

**集成方法：**
- 扩展现有User模型添加phone字段
- 新增PhoneAuth路由复用现有token生成逻辑
- 前端新增PhoneAuth组件整合进现有登录界面

**现有模式参考：**
- 参照 `backend/open_webui/apps/webui/models/users.py` 的User模型设计
- 复用 `backend/open_webui/utils/utils.py` 的JWT工具函数
- 前端遵循 `src/routes/(app)/auth/+page.svelte` 的界面模式

**关键约束：**
- 必须向后兼容现有用户数据
- 不得修改现有认证接口行为
- 短信服务通过环境变量配置

## 风险和兼容性检查

**最小风险评估：**
- 主要风险: 短信服务依赖可能导致认证不可用
- 缓解策略: 保留现有认证方式作为备用方案
- 回滚方案: 禁用手机认证路由，恢复纯用户名认证

**兼容性验证：**
- [x] 现有API无破坏性变更
- [x] 数据库变更仅为添加字段
- [x] UI变更遵循现有TailwindCSS设计
- [x] 性能影响可忽略不计
