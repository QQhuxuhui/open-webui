# Story 2.1: 强制手机号注册认证系统

## User Story

作为汉云WebUI的产品负责人，我希望强制所有用户使用手机号注册和登录，以便确保用户实名认证和提高账户安全性。

## Story Context

**现有系统集成：**
- 集成对象: 现有多重认证系统 (`backend/open_webui/routers/auths.py`)
- 技术栈: FastAPI + Svelte + JWT + PhoneAuth组件
- 遵循模式: 现有认证模式，禁用邮箱认证
- 接触点: 认证路由、前端认证界面、配置系统

**Epic背景：**
Epic 2: 认证系统增强 - 基于架构师核查清单发现的需求

## 验收标准

**功能需求：**
1. 用户注册时只能使用手机号+验证码，移除邮箱注册选项
2. 用户登录时只能使用手机号+验证码，移除邮箱登录选项
3. 系统通过环境变量控制认证方式（ENABLE_EMAIL_AUTH=false）
4. 现有邮箱用户可以绑定手机号后继续使用
5. 前端界面默认显示手机认证，隐藏邮箱认证选项

**集成要求：**
6. 现有手机认证功能保持完全不变
7. JWT token生成和验证逻辑保持一致
8. 现有用户数据向后兼容，不影响老用户
9. OAuth第三方登录功能保持不变

**质量要求：**
10. 包含完整的前后端集成测试
11. 邮箱认证API在配置禁用时返回明确错误信息
12. 前端UI提供清晰的手机认证指导

## 技术实现细节

- 添加环境变量配置开关控制认证方式
- 修改前端认证界面默认显示手机认证
- 后端API增加配置验证，禁用邮箱认证端点
- 保持现有手机认证逻辑不变

## Dev Notes

**现有架构分析：**
基于代码分析，当前系统支持4种认证方式：
1. ✅ `/signup` - 邮箱注册 (需要禁用)
2. ✅ `/signin` - 邮箱登录 (需要禁用)
3. ✅ `/phone/signup` - 手机注册 (保留)
4. ✅ `/phone/signin` - 手机登录 (保留)

**前端模式管理：**
- 当前使用 `mode` 变量控制界面：`signin`、`signup`、`phone-signin`、`phone-signup`
- 需要修改默认模式为 `phone-signin`
- 需要隐藏邮箱认证切换按钮

**配置集成点：**
- 现有配置系统：`$config?.features.enable_login_form`
- 新增配置：`$config?.features.enable_email_auth` (默认false)
- 环境变量：`ENABLE_EMAIL_AUTH`、`FORCE_PHONE_AUTH`

**数据兼容性：**
- User表已包含 `phone` 字段和 `email` 字段
- 现有用户可以通过绑定手机号继续使用
- PhoneVerification表已完整实现
