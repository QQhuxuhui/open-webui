# Open-WebUI 中国合规性增强 PRD

## 项目分析与背景

### 现有项目概览

**分析来源：** IDE-based 实时项目分析

**当前项目状态：**
Open-WebUI 是一个功能强大的AI聊天界面项目，主要目的是为用户提供与各种大语言模型交互的Web界面。

**技术栈架构：**
- **前端：** Svelte/SvelteKit + TypeScript + TailwindCSS
- **后端：** FastAPI + Python (3.11-3.12)  
- **数据库：** SQLite/PostgreSQL (通过 Peewee ORM)
- **认证：** JWT + Passlib + Python-JOSE
- **实时通信：** Socket.IO
- **构建工具：** Vite + Node.js >=18.13.0

### 增强描述
为Open-WebUI添加符合中国法规要求的用户认证、内容标识、举报反馈和个人信息管理功能，确保平台在中国市场的合规运营。

### 目标与背景

**目标：**
- 实现中国法规要求的手机号实名认证注册登录系统
- 为AI生成内容添加规范化的标识和水印机制
- 提供完整的用户举报反馈渠道
- 建立用户个人信息管理和实名认证体系

**背景：** 
根据中国《深度伪造规定》、《算法推荐管理规定》等相关法规，AI应用需要明确标识AI生成内容，提供用户举报功能，并实施实名认证制度。

## 功能需求

### 功能需求

**FR1：手机号验证码注册登录系统**
- 用户可通过手机号接收验证码完成注册，替换或补充现有的用户名/邮箱注册方式
- 集成现有的JWT认证系统，保持与当前session管理的兼容性
- 注册流程必须包含《隐私协议》和《服务协议》的勾选确认机制

**FR2：AI生成内容标识系统**  
- 所有LLM响应在聊天界面下方显示"内容由AI生成，仅供参考"的文字标识
- 系统自动检测AI生成的图片和视频内容
- 在AI生成的图片/视频四角之一添加"内容由AI生成"水印，水印应不影响内容可读性但清晰可见

**FR3：用户举报反馈功能**
- 在每条AI生成内容下方提供举报按钮
- 全局导航中提供反馈入口
- 举报内容应包括：不当内容、技术问题、版权问题等分类选项
- 提供文本描述和截图上传功能

**FR4：个人信息管理系统**
- 在用户中心添加"编辑资料"功能模块
- 支持修改手机号、昵称、头像等基本信息
- 集成现有的用户设置界面，保持UI一致性

**FR5：实名认证功能**
- 提供身份证号码和姓名验证
- 支持身份证照片上传和OCR识别（可选）
- 认证状态在用户资料中显示
- 认证信息加密存储，符合数据保护要求

### 非功能需求

**NFR1：性能要求**
- 验证码发送响应时间 ≤ 3秒
- AI内容标识不应增加页面渲染时间超过100ms
- 个人信息更新操作响应时间 ≤ 2秒

**NFR2：安全要求**
- 手机验证码采用6位数字，5分钟内有效
- 实名认证信息采用AES-256加密存储
- 举报数据需要访问日志记录
- 验证码发送频率限制：每分钟最多1次，每小时最多5次

**NFR3：可用性要求**
- 支持主流移动设备的响应式设计
- AI内容标识支持多语言（中文、英文）
- 举报功能应在网络不稳定时支持离线提交

**NFR4：兼容性要求**
- 必须兼容现有用户数据，支持老用户平滑迁移到新认证系统
- 保持与现有OpenAI、Anthropic等API集成的完全兼容
- 新功能不应破坏现有的聊天、文件上传、模型切换等核心功能

### 兼容性需求

**CR1：现有API兼容性** - 所有新增认证接口必须与现有的`/api/v1/auths/`路径保持一致的响应格式

**CR2：数据库模式兼容性** - 用户表扩展必须通过Peewee迁移实现，不破坏现有用户数据

**CR3：UI/UX一致性** - 新增界面必须遵循现有的TailwindCSS设计系统和Svelte组件模式

**CR4：集成兼容性** - 新功能必须与现有的Socket.IO实时通信、文件上传、多模型支持等功能无缝集成

## 技术约束和集成要求

### 现有技术栈
**语言**: Python 3.11+ (后端), TypeScript (前端)
**框架**: FastAPI + Svelte/SvelteKit
**数据库**: SQLite/PostgreSQL + Peewee ORM  
**认证**: JWT + Passlib
**基础设施**: Docker + Uvicorn

### 集成策略
**数据库集成**: 扩展现有User表，新增PhoneAuth、UserProfile、ReportFeedback表
**API集成**: 扩展`/api/v1/auths/`路径，新增`/api/v1/compliance/`路径
**前端集成**: 在现有Svelte组件基础上新增PhoneAuth、ContentLabel、ReportModal组件
**测试集成**: 扩展现有pytest和cypress测试套件

### 代码组织标准
**文件结构**: 
- 后端: `backend/open_webui/apps/webui/routers/compliance.py`
- 前端: `src/lib/components/compliance/`
**命名约定**: 遵循现有camelCase(前端)和snake_case(后端)
**编码标准**: 使用现有Black+ESLint配置

### 部署和运维
**构建过程集成**: 扩展现有npm run build和Docker构建流程
**部署策略**: 向后兼容的数据库迁移，零停机部署
**监控和日志**: 复用现有loguru日志系统，新增合规性操作日志
**配置管理**: 通过环境变量管理短信服务配置

### 风险评估和缓解
**技术风险**: 短信服务依赖 - 提供多服务商支持和降级方案
**集成风险**: UI组件冲突 - 采用命名空间和独立样式
**部署风险**: 数据库迁移失败 - 提供回滚脚本和备份策略
**缓解策略**: 分阶段部署、功能开关、全面测试覆盖

## 史诗和故事结构

### Epic 1: 中国合规性功能增强

**Epic目标**: 为Open-WebUI添加符合中国法规的认证、标识、举报和个人信息管理功能

**集成要求**: 与现有JWT认证、聊天系统、用户管理完全兼容

### Story 1.1: 手机验证码认证系统
作为用户，我希望使用手机号和验证码注册登录，以便符合实名认证要求。

**验收标准**:
1. 用户可输入手机号接收6位验证码
2. 验证码5分钟有效，支持重发
3. 注册时必须勾选隐私协议和服务协议
4. 成功后获得JWT token，兼容现有认证流程

**集成验证**:
- IV1: 现有用户名/密码登录功能保持不变
- IV2: JWT token格式和有效期与现有系统一致  
- IV3: 用户session管理无影响

### Story 1.2: AI内容标识系统
作为用户，我希望看到AI生成内容的明确标识，以便区分人工和AI内容。

**验收标准**:
1. 所有AI响应下方显示"内容由AI生成，仅供参考"
2. AI生成图片/视频自动添加透明水印
3. 支持中英文标识切换
4. 标识样式与现有UI保持一致

**集成验证**:
- IV1: 现有聊天消息格式不受影响
- IV2: 图片/视频上传和显示功能正常
- IV3: 多模型支持(OpenAI/Claude/本地模型)均正常标识

### Story 1.3: 举报反馈功能
作为用户，我希望能举报不当内容或提供反馈，以便维护平台内容质量。

**验收标准**:
1. 每条AI内容下方显示举报按钮
2. 支持分类举报(不当内容/技术问题/版权)
3. 可添加文字描述和上传截图
4. 全局导航提供反馈入口

**集成验证**:
- IV1: 聊天界面布局和交互不受影响
- IV2: 文件上传功能复用现有组件
- IV3: 举报数据独立存储不影响聊天记录

### Story 1.4: 个人信息管理和实名认证
作为用户，我希望管理个人信息并完成实名认证，以便获得更好的服务体验。

**验收标准**:
1. 用户中心新增"编辑资料"模块
2. 支持修改手机号、昵称、头像
3. 提供实名认证功能(姓名+身份证)
4. 认证状态在个人资料显示

**集成验证**:
- IV1: 现有用户设置界面和功能保持完整
- IV2: 头像上传复用现有文件处理逻辑
- IV3: 用户数据安全加密存储
